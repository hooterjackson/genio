# gênio QA sweep — 2026-07-17

## Local evidence

This sweep exercised the deterministic research-policy and playlist-assembly
layers without calling paid OpenAI or live Apple services.

- `pnpm qa:policy:check`: 170 policy and regression tests passed.
- `pnpm test`: 494 tests passed and 94 database/provider-gated tests were
  skipped in the local, credential-free run.
- Application and server TypeScript checks passed.
- Targeted ESLint and `git diff --check` passed for the changed policy,
  selection, title, and scenario files.

These results are local evidence, not a production release result. Database,
responsive-browser, hosted-provider, and deployment checks below still need
their own environment and must not be inferred from the deterministic run.

## Scenario coverage

The release corpus and focused tests cover:

- Exact 1–300-track targets, bounded candidate reserves, under-yield, catalog
  shortfall, explicit failure, and complete candidate accounting.
- Numbers that are musical context rather than requested size: duration,
  years, `12-tone`, and numeric artist names such as `808 State`.
- Similar-to prompts with one or more seed artists, default seed exclusion,
  artist-diverse reserve selection, and titles that describe the result rather
  than naming it as the excluded artist's own playlist.
- Sequence assembly that separates repeated artists and albums while
  preserving the selected membership and requested ordering policy.
- Esoteric prompts spanning Sahrawi electric-guitar music, Wandelweiser,
  funaná, gwo ka moderne, Japanese environmental music, daxophone works,
  dub-techno exchange, and documented session-player credits.
- Archived production attempts replayed through deterministic under-yield and
  Apple-recovery tapes, including failures and budget-gated attempts.
- The public playlist directory's privacy projection, stable Apple-link
  filtering, pagination, out-of-range handling, multi-volume states, owner
  hide/relist controls, and preservation after private run deletion.

## Defects addressed in this sweep

- Similarity-playlist selection could consume the accepted reserve in rank
  order and return a large block from one artist. It now applies progressive
  per-artist caps while still filling the exact target when the pool is sparse.
- Similarity prompts could inherit a stale or misleading source-artist title.
  Titles are normalized after final scope repair, for example
  `Beyond Radiohead: 50 Similar Tracks`.
- The adversarial corpus did not explicitly protect long-duration wording,
  numeric artist names, multi-seed similarity, or Sahrawi music requests.
  Those cases are now frozen regression scenarios.

## Harness commands

Fast deterministic release feedback:

```sh
pnpm qa:policy:check
pnpm qa:scenarios:check
pnpm test
pnpm lint
pnpm build
```

Database checks require a disposable Postgres 17 database. The preflight
refuses a remote host unless the operator explicitly opts into an isolated
remote test database.

```sh
docker compose up -d postgres
export DATABASE_URL=postgresql://needle:needle@127.0.0.1:5432/needle
pnpm test:database:preflight
pnpm db:migrate
pnpm test:coverage
```

Responsive browser checks use an isolated local preview and test the four
configured projects independently:

```sh
pnpm exec playwright install chromium webkit
pnpm test:e2e --project=mobile-320
pnpm test:e2e --project=mobile-390
pnpm test:e2e --project=mobile-430
pnpm test:e2e --project=desktop
```

CI runs static/build, policy, Postgres-backed coverage, and the four browser
projects as separate jobs. A green local deterministic run does not replace a
green CI run.

## Required CI and live-provider validation

Before production promotion:

1. Run the complete CI workflow on the release revision, including fresh
   migrations, Postgres integration tests, coverage thresholds, and all four
   Playwright projects.
2. Run capped staging OpenAI canaries for a common request, similarity request,
   ambiguous entity, esoteric request, and catalog-recovery request. Review
   relevance and citations against independent expectations.
3. Verify the real US Apple storefront: authorization survives restart,
   matching recovers known catalog tracks, the approved manifest count and
   order are exact, and every volume receives a stable public
   `music.apple.com` link.
4. Verify the public link can be added from a second Apple Music account.
5. Smoke-test `/playlists` anonymously against production data: newest-first
   pagination, ordered multi-volume links, no private fields, and owner
   hide/relist behavior.
6. Export and redact retained production attempts, promote every new failure
   mode to the frozen fixture, and rerun `pnpm qa:scenarios:check`.

promotion rules and [`phase-zero.md`](phase-zero.md) for the live Apple gates.
