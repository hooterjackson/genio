# 9ênio QA sweep — 2026-07-16

## Result

The deterministic release-candidate suite is green:

- 558 Vitest unit and Postgres integration tests passed in 38 files.
- 168 Playwright tests passed across 320 px, 390 px, 430 px, and desktop.
- ESLint passed with no warnings or errors.
- The Vinext production build passed for `/`, `/feedback`, `/owner`, and
  `/privacy`.
- Application and server TypeScript checks passed.
- `git diff --check` passed.
- `https://9enio.com/` returned HTTP 200 during the final operational check.

No paid OpenAI research, live Apple catalog write, or Apple playlist
publication was performed in this sweep. Those checks remain separate,
owner-approved canaries so offline test success is never presented as factual
music-research or live-publication proof.

## Esoteric workload scenarios

The offline corpus includes the following deliberately difficult requests:

- Wandelweiser-adjacent lowercase improvisation.
- Guadeloupean gwo ka moderne and cadence-lypso crossover.
- Japanese environmental music from 1980–1989.
- Pre-1990 Cape Verdean funaná excluding morna.
- South African bubblegum and Shangaan disco before 1994.
- Tamil film songs with lead nadaswaram.
- Electroacoustic daxophone, glass harmonica, and prepared-zither works.
- Belgian new beat original mixes from 1987–1990.
- The Bristol–Berlin dub-techno exchange.
- Privately issued North American minimal synth from 1978–1985.
- Buchla tape works, Greenlandic metal/drum-song crossover, Indonesian
  jaipongan club selections, spectralist-influenced black metal, and Inuit
  throat-singing/electroacoustic collaborations.
- Track-level Paulinho da Costa, Hal Blaine, Alice Coltrane/Pharoah Sanders,
  and non-primary-artist Prince guitar-credit enumeration.

These tests prove deterministic workload policy: explicit count handling,
bounded fast routing and cost, candidate reserve sizing, similarity-seed
exclusion, and exhaustive-versus-curated mode boundaries. They do **not** prove
that a live model found the correct canon, that every item has sufficient
evidence, or that every item is available in the owner's Apple storefront.
Each provider-backed esoteric scenario still needs an independently reviewed
holdout and a capped staging run.

## Defects found and fixed

### Research and count policy

1. Explicit counts were lost for esoteric nouns such as “works,” “pieces,”
   “compositions,” “cuts,” “selections,” and “collaborations.” The count parser
   now recognizes them.
2. Requests below 20 tracks had no matching reserve, so one unavailable Apple
   result forced a terminal shortfall. Small playlists now receive a bounded
   reserve of at least three candidates.
3. Hyphenated `X-adjacent` prompts did not consistently exclude the reference
   artist. Shorthand similarity seeds now receive the same default exclusion
   policy as “sounds like X.”
4. The literal artist `X` could be erased as a collaboration delimiter, and a
   punctuation-only artist such as `!!!` could evade exclusion. Artist-credit
   normalization now preserves both identities.

5. Numeric descriptors such as “20 years of techno tracks,” “12-tone works,”
   and “60-minute ambient tracks” could be mistaken for playlist sizes. Unit
   and descriptor guards now keep those numbers in the musical scope.
6. Reserve sizing jumped from 29 candidates for 19 tracks to 70 for 20 tracks.
   The reserve now follows a smooth, bounded 50% curve with a three-candidate
   floor.

### Apple catalog matching

7. A merely compatible artist variant could stop the query ladder before a
   later exact artist match was found. Only a direct exact result now stops the
   ladder.
8. An exact artist/title match on the wrong album edition could stop before an
   album-specific query. When source album metadata exists, the direct stop
   now requires that album.
9. A unique exact artist/title/album result without source duration remained
   review-only. It can now be accepted when unique and version-compatible;
   supplied duration still has to agree strictly.
10. A version-labeled candidate with neither album nor duration could be
    auto-accepted from artist/title alone. It now requires a supplied exact
    album or duration; otherwise it stays in review.
11. Sparse-metadata canonical-family selection could lose precedence to a
   lower-confidence result. The accepted match now consistently uses the
   deterministic canonical sparse match when present.

### Mobile, accessibility, and hydration

12. The mobile `JOBS` action was smaller than the 44 px touch-target minimum.
13. Job rows had ambiguous accessible names. They now announce playlist title
    and status.
14. Feedback text entered during hydration could be discarded. Form controls
    remain disabled until the client is ready.
15. The native `<details>` menu could race hydration and intermittently hide
    navigation. It is now state-controlled, exposes `aria-expanded`, closes on
    outside click or Escape, and restores trigger focus.

### QA infrastructure

16. Miniflare did not receive the local `OWNER_EMAIL` binding, so owner tests
    could not authenticate.
17. Playwright reused unrelated port-3000 previews and silently skipped owner
    coverage. Browser QA now starts an isolated server on port 4173 and a
    missing allowlist fails the test instead of skipping it.
18. The backend integration fixture hard-coded migrations only through `0009`,
    leaving the test schema behind the current schema version. It now discovers
    every numbered migration dynamically.
19. The transfer-capability expiry fixture compared an API-host timestamp only
    one millisecond in the past with the database host's clock. It now expires
    the token using PostgreSQL's own clock, eliminating cross-host skew without
    changing production TTL behavior.

## Required provider and live gates

The following are not reproducible by mocks and remain required before calling
the entire production system validated:

1. Run capped OpenAI canaries for a normal prompt, similarity prompt,
   ambiguous entity, extremely esoteric prompt, and Apple-recovery prompt.
2. Judge factual relevance and citation quality against independent holdouts;
   do not use the model's own output as the expected answer.
3. Verify real US-storefront Apple matching, MusicKit authorization persistence
   across restart, automatic publication, exact order, stable public share
   link, and second-account Add to Library.
4. Verify arbitrary artist/era/label exclusions and per-artist/per-album caps
   with hostile provider tapes; current deterministic coverage is strongest for
   reference-artist and recording-version exclusions.
5. Implement and test the public playlist directory before treating US-12 as a
   shipped feature.
6. Retain every redacted production attempt as a future regression scenario,
   especially failures, cost overruns, catalog shortfalls, and unusual prompts.

## Reproduction

Portable project commands:

```sh
docker compose up -d postgres
DATABASE_URL=postgres://needle:needle@localhost:5432/needle pnpm test
pnpm lint
pnpm build
pnpm test:e2e
docker compose stop postgres
```

The browser config starts a dedicated local preview and supplies only the test
owner identity. It no longer depends on whatever developer preview happens to
be running on port 3000.
